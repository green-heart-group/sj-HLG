# Demo 后续计划

当前进度见 [status.md](status.md)。

## 优先级 1：数据拆分

- 将 `achievementData` 从 HTML 拆为 `data/achievements-main.json`。
- 将节点、物品、事件、商店池、敌对实体拆为独立 JSON，页面启动时加载，便于策划案迭代后替换数据。
- 界面代码拆为 `src/ui/*.js` 等模块。

## 优先级 2：成就系统补全

- 继续从[原策划案·成就系统](../design/achievements.md)抽取彩蛋成就、场景收录、人物信息。
- 四类分 Tab 展示，不挤在同一张大图中。
- 隐藏成就按原案规则：未揭示时完全不可见，前置达成后再出现。

## 优先级 3：战斗节点设计

从「掷骰击退」扩展为贴合各实体背景的模式（实体设定见[原策划案·实体机制](../design/entities.md)）：

- WXH：追逐压迫型。核心不是击败，而是利用酒精灯、溶液、肥皂线索削弱并摆脱追踪。
- ZYY：电流判定型。核心是观察、充能、过载与规避；失败造成体力/理智损伤，成功推进怒霆雷跃线。
- SGF：地形机关型。核心是深坑、高炉、地形变化与煤炭/钥匙/靴子的联动。
- LJX：空间弹道型。核心是一横圣器的直线视野、直线攻击、爆炸范围与地牢格局。
- MJ/被同化者：群体/感染型。核心是被包围、复制、同化、利用掉落物反制，而不是传统单体血量战。

统一抽象为「遭遇回合」：

- 玩家每回合选择：观察、使用物品、移动/躲避、攻击/击退、逃离。
- 敌对实体每回合执行：逼近、封路、施加异常、复制、召唤、地形改变。
- 胜利条件按实体变化：击退、弱化、解谜、撑过回合、取得物品、逃离节点。
